# 002 · kiban public API (contract)

Status: **implemented in 0.2.0** (2026-11-18; items in §4 done and checked on the device, research/003 "0.2.0 checks"). Describes the API products (bunko, manabu) may rely on, the rules behind it,
and the changes planned for version 0.2.0. Measured facts are referenced as research/003 sections.

## 1. Consuming kiban

```yaml
# product main/idf_component.yml
dependencies:
  kiban:
    git: https://github.com/patricksuo/kiban.git
    path: components/kiban
    version: "v0.3.0"        # a git tag; products pin a tag, never a branch
  kiban_net:                 # optional; requires kiban at the same version
    git: https://github.com/patricksuo/kiban.git
    path: components/kiban_net
    version: "v0.3.0"
  kiban_usb:                 # optional; requires kiban at the same version (§5.2)
    git: https://github.com/patricksuo/kiban.git
    path: components/kiban_usb
    version: "v0.3.0"
```

`kiban_net` and `kiban_usb` do not declare `kiban` in their manifests (a relative path would not resolve when
fetched from git); they name it in CMake `REQUIRES`, so products list both. `kiban_usb` declares its registry
dependency `espressif/esp_tinyusb` itself.

Versioning: semantic. Any change to a public header that can break a product bumps the minor version while < 1.0
(0.1.0 → 0.2.0 for the charger split) and is listed in the release notes with its impact on bunko and manabu.

## 2. Global rules

| Rule | Detail |
|---|---|
| Language | Pure C, `esp_err_t` returns, no C++ in public headers |
| Waits | Every hardware wait is bounded (timeout argument or documented constant). The vendor firmware waits forever in several places |
| Tasks | kiban creates no hidden tasks. The audio driver uses the I2S driver's DMA; `kiban_battery_poll` etc. run in the caller's task |
| Threading | The shared I2C layer is locked (one transaction at a time). The charger and TCA9555 read-modify-write paths have their own mutex. Other drivers (EPD, touch, audio, SD) are **not** re-entrant: one owner task each |
| NVS | kiban never calls `nvs_flash_init`. The stock `nvs` partition holds the vendor's Wi-Fi credentials and device identity and must not be opened by products either (see D1) |
| Stack | Code that performs TLS handshakes needs ≥ 16 KB of stack (4 KB overflowed, research/003 Wi-Fi) |
| Charging | The charge policy is enforced at every `kiban_board_init()`; VREG ≤ 4200 mV until the cell rating is confirmed; fail closed |

## 3. Headers

| Header | Responsibility | Blocking | Evidence |
|---|---|---|---|
| `board.h` | Bring-up order, pin map, shared I2C bus, rails, charge policy at init | init ≤ ~3.5 s (expander retry window) | P0, P1, Charge policy |
| `ioexp.h` | TCA9555 registers; RMW set/get. Low level: products normally use `keys.h` / `board.h` | 50 ms per transfer | P1 |
| `epd.h` | SSD1677: init, FULL / FAST / PARTIAL / FULL_OTP, 4-gray overlay, sleep; frame 800×480 landscape | BUSY ≤ `CONFIG_KIBAN_EPD_BUSY_TIMEOUT_MS` (5 s) | P2 |
| `touch.h` | CST816S reads, sleep, reset; cover-key decoding | 20 ms per read; NACK while idle is normal | P3 |
| `keys.h` (new) | Debounced key events: POWER, AI (BOOT), VOL+, VOL−, cover LEFT / MIDDLE / RIGHT | non-blocking poll | P1 keys, P3 |
| `sensors.h` | BQ27220 reads (V/I/T meaningful; its SOC is not), PCF8563, SC7A20H | 50 ms per transfer | P4, gauge configuration |
| `charger.h` | CX25601N status, dump, policy apply, enable/disable | ~10 transfers | Charge policy |
| `battery_soc.h` | Pure SOC estimator (coulomb counting + anchors + gap handling) | none | host tests |
| `battery.h` | `kiban_battery_poll`: gauge + charger + temperature gate + SOC | ~10 transfers | Charge policy |
| `sdcard.h` | SDMMC 1-bit FAT mount, never formats; `kiban_sd_mount_point()`; raw card open/close (`kiban_sd_raw_open` / `kiban_sd_raw_close`, used by `kiban_usb`; mutually exclusive with the FAT mount) | mount ~40 ms | P5; raw open: 001 §8 U1 |
| `haptic.h` | Motor pulse | blocks for the pulse | P5 |
| `audio.h` | BT module: AT handshake, I2S slave out/in, amp, DMA ring size | open ~2.7 s; I/O bounded by timeout args | P6 |
| `power.h` | Quiesce, light/deep sleep, hardware power-off, timed power-off | power-off ≤ 5 s then returns | P7 |

## 4. Changes for 0.2.0

Already done (since 0.1.0): charger split out of `sensors.h` into `charger.h` (incompatible), `battery.h`,
`battery_soc.h`, shared I2C lock, gauge configuration functions removed.

To implement in this round:

1. **`keys.h`** (new). `kiban_keys_init()`, `kiban_keys_poll(int64_t now_us, kiban_key_event_t *ev, size_t max)`.
   Events: press, release, long press (default 600 ms), for POWER (GPIO3, external pull-up), AI (GPIO0, **internal
   pull-up required**, strapping pin, never driven), VOL+ (P1.0), VOL− (P0.7), cover LEFT / MIDDLE / RIGHT.
   Debounce 20 ms. **Polling only**: TCA9555 P1.2 toggles on its own and pulses the expander INT (GPIO2), so GPIO2 is
   not usable as an interrupt or wake source (research/003 P7). Cover keys are named by **physical position**; their
   meaning (home / previous / next) is product policy.
2. **`touch.h`**: `kiban_touch_cover_key(x, y)` → LEFT (80,900) / MIDDLE (400,900) / RIGHT (240,900) / NONE, as
   measured (the vendor source comments swap MIDDLE and RIGHT). The +15..+22 px y offset of finger taps is documented,
   not corrected in the driver.
3. **`epd.h`**: portrait helpers `KIBAN_EPD_PORTRAIT_W/H` and an inline pixel setter implementing the measured mapping
   portrait (px, py) → frame (fx = py, fy = 479 − px). No drawing library.
4. **RTC** (`sensors.h`): `kiban_rtc_set()` (also clears the VL "integrity lost" flag); `kiban_rtc_wake_after(seconds)`
   picking the 1 Hz source up to 255 s and the 1/60 Hz source (minute resolution) up to 255 min.
5. **`power.h`**: `kiban_power_prepare()` closes everything kiban owns (amp, audio, touch, panel, SD);
   `kiban_power_off_for(seconds)` = prepare + RTC wake + power-off, falling back to deep sleep with the same timer if
   power stays on. The ≥ 255 s path (1/60 Hz) is new and must be verified on the device (USB re-enumeration shows the
   wake; no user action).
6. **B1 diagnostic**: `kiban_board_boot_info()` returns the expander's output/config registers read **before** init
   and the reset reason, so a real power-off can show whether the TCA9555 lost power (research/003 states it keeps
   state across the stock long-press off, which may not have cut power).
7. **Probe**: commands become thin shells over the API; self-check after the change: `info`, `i2c_scan`, `chg`,
   `battery`, `epd full marker`.
8. **Consumer check**: a throwaway ESP-IDF project in a scratch directory depends on kiban by git tag and builds.

## 5. Layers

| Layer | Criterion | Where |
|---|---|---|
| Board | Depends on this board's hardware facts | `components/kiban` |
| Shared capability | Needed by both products, not board-specific | optional components in this repo, e.g. `components/kiban_net`; products depend on them explicitly |
| Product policy | UI, UX or product decisions (which network, when to sync, how to provision) | bunko / manabu |

(Same split as FreeInk SDK: `libs/hardware` has no connection code; network features are opt-in libraries.)

### 5.1 `kiban_net` (optional component, 0.2.0)

Depends on `kiban` (RTC). Requires in the product's `sdkconfig.defaults`: `CONFIG_ESP_WIFI_NVS_ENABLED=n`,
`CONFIG_ESP_PHY_CALIBRATION_AND_DATA_STORAGE=n` (and `CONFIG_BT_NIMBLE_NVS_PERSIST=n` if BLE is used), and
`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY=y` (W1: chains topped by a certificate cross-signed by a root
that is no longer in the IDF bundle, e.g. GTS Root R4 cross-signed by GlobalSign Root CA, fail without it). Callers that
run TLS need ≥ 16 KB of stack.

| Header | API | Notes |
|---|---|---|
| `kiban_net/wifi.h` | `kiban_wifi_init`, `kiban_wifi_connect(cfg)`, `kiban_wifi_disconnect`, `kiban_wifi_connected`, `kiban_wifi_rssi`, `kiban_wifi_scan`, `kiban_wifi_deinit` | STA only; credentials passed by the caller and kept in RAM (`WIFI_STORAGE_RAM`); connect blocks with retries (PMF capable, SAE both); where credentials are stored is product policy |
| `kiban_net/http.h` | `kiban_http_get(cfg, sink, ctx, result)`, `kiban_http_download(url, path, opts, result)` | Streaming GET into a callback; file download writes `path.part`, resumes with `Range`, renames on completion; TLS via the IDF certificate bundle or a caller-supplied CA (W1) |
| `kiban_net/time.h` | `kiban_time_sync(timeout_ms)` | SNTP; sets the system clock and writes the PCF8563 in UTC (clears its VL flag) |

### 5.2 `kiban_usb` (optional component, 0.3.0)

USB drive mode: the SD card exported to a USB host as a mass-storage device. Ported from the vendor firmware's
virtual disk (research/001 §5.3, `usb_virtual_disk.cc`) [source]; nothing here is measured yet (open item U1 in
001 §8). Depends on `kiban` (`sdcard.h`, `ioexp.h`) and `espressif/esp_tinyusb` `~2.4.0` (the vendor uses `^2.0.0`
with the same API; 3.x is not used). Requires in the product's `sdkconfig.defaults`: `CONFIG_TINYUSB_MSC_ENABLED=y`
(the build fails with an `#error` otherwise). ESP32-S3 only.

| Header | API | Notes |
|---|---|---|
| `kiban_usb/usb_drive.h` | `kiban_usb_drive_start`, `kiban_usb_drive_stop`, `kiban_usb_drive_active`, `kiban_usb_host_mounted`, `kiban_usb_host_ejected` | Not re-entrant: one owner task |

Behaviour:

- **One PHY.** The ESP32-S3 has a single USB full-speed PHY (GPIO19/20) shared by USB-Serial/JTAG and USB-OTG.
  Start routes it to OTG (`usb_serial_jtag_ll_phy_enable_pad(false)` + `phy_enable_external(true)`, then
  `usb_new_phy(OTG, INT)` owned by kiban_usb, TinyUSB installed with `phy.skip_setup`). While active, the
  USB-Serial/JTAG console and esptool auto-reset are gone. Stop: `tud_disconnect` → 200 ms for deferred MSC
  writes → `tinyusb_driver_uninstall` → `usb_del_phy` → 150 ms → route to USB-Serial/JTAG → 100 ms (vendor order
  and delays, plus the disconnect and drain). Stop while inactive only routes the PHY back, so products call it
  once at boot in case a reset left the PHY on OTG [to-verify whether the selection survives a reset].
- **Product duty:** a way to leave drive mode without the console (a key, a timeout, leaving the screen; the
  vendor forces it off when its settings page is left). The probe stops on a timeout or a POWER key press.
- **SD card.** Start remembers the mount point and clock, unmounts the FAT volume (callers close their files
  first) and opens the card raw (`kiban_sd_raw_open`); stop remounts it the same way, or leaves it unmounted if
  it was unmounted at start. The storage is created owned by the USB host with `auto_mount_off` and
  `do_not_format`: esp_tinyusb never mounts or formats the card for the app (unlike the vendor, which switches
  the card between app and host).
- **Power:** stop drive mode before any `kiban_power_*` call (`kiban_power_prepare()` does not know about the
  raw card or TinyUSB; the vendor blocks standby while its virtual disk is on).
- **USB mux** (TCA9555 P0.0) must be high (ESP); start reads it and refuses if low, never writes it.
- **Host state.** `kiban_usb_host_mounted()` = the host configured the device (TinyUSB attach/detach events). `kiban_usb_host_ejected()` = the host ejected the drive (SCSI eject; writes flushed, medium now "not present"); the product then calls `kiban_usb_drive_stop()`. Do not end drive mode on a timer while the host has the volume mounted.
  A host-side eject is not reported (esp_tinyusb owns the SCSI eject callback). Stopping while the host writes
  looks like an unplug to the host and can leave the FAT volume inconsistent: products ask the user to eject first.
- **Failure.** Start rolls everything back on failure. If teardown fails (TinyUSB task not stopped, MSC storage
  not released), stop returns `ESP_ERR_INVALID_STATE`, the card stays unmounted and start refuses until a reboot.
- **Tasks.** TinyUSB runs its own task while active (default 4 KB stack, priority 5): the one exception to
  "kiban creates no hidden tasks". MSC buffer `CONFIG_TINYUSB_MSC_BUFSIZE` = 512 (esp_tinyusb default on S3,
  as in the vendor build); throughput is not measured.
- USB identity: Espressif VID `0x303A`, PID `0x4002` (as in the vendor firmware), strings `kiban` /
  `E-Ink 4 SD card`.

Out of all kiban components: BLE (no product need yet), provisioning UI, fonts, layout, content formats, playback
policy.
## 6. Decisions needed

- **D1 · Persistent storage — decided (user, 2026-11-18): (a)** a new partition table with a product-owned NVS
  partition; the stock bootloader stays, the stock table is replaced (recoverable from the full backup). The table
